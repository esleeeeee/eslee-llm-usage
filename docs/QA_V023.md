전체 Android 테스트는 Pixel 7 기반 API 35 google_apis x86_64 에뮬레이터를 720×1280, density 320(360×640dp), 글꼴 130%, 화면 키보드 켜짐으로 설정해 실행했다. 한국어 추가 검증은 기본 1080×2400, density 420, 글꼴 100%에서 실행했다. WHPX 하드웨어 가속, JDK 21.0.12.1, SDK 37.0/build-tools 36.0.0을 사용했다.

## 실제로 실행한 범위

- 앱: 계정 카드 → 전체 갱신 → 새 snapshot 저장, 라이트/다크 전환, 상태바 대비, 상세 → 이름 변경 → 삭제 취소 → 삭제 완료 → 빈 화면.
- API 계정 추가: 작은 화면과 열린 키보드에서 폼 스크롤, 저장 버튼 접근, 마스킹 입력, 검증 전 상태 저장. 실제 API 요청은 하지 않음.
- WebView: 서로 다른 계정 쿠키/localStorage 격리, A 삭제 후 데이터 제거/재사용 차단, B 데이터 유지. 로드된 profile의 즉시 삭제가 금지되는 플랫폼 제약을 재현한 뒤 수정.
- 수집: 지연 렌더링 페이지 읽기, 기존 세션 재사용, DB 지속 저장, 반복 갱신에 따른 실제 RemoteViews 값 변경, 실패 시 마지막 성공 데이터 유지.
- 위젯: 실제 AppWidgetHost에 위젯을 바인딩하고 production 새로고침 콜백 → WorkManager 작업 → Demo 계정 두 개 갱신 → 상태 해제를 두 번 확인. 콜백은 테스트에서 직접 호출했으며 런처의 손가락 탭을 흉내 낸 것은 아님.
- 위젯 렌더: 72×56, 72×96, 160×100, 220×150, 320×100, 320×200, 360×480dp. 실제 0, 100, unknown, 긴 이름, 실패/오래된 상태를 구분.
- Room 스키마/데이터 보존 및 Keystore credential 검증.

## 재현과 증거

`scripts/verify-windows.ps1 -Connected`로 빌드와 전체 테스트를 실행한다. 한글 경로의 JVM class loading 실패를 피하도록 원본 폴더를 가리키는 영문 junction을 사용한다. 원본 파일을 옮기지 않는다.

로컬 상세 로그는 ignored `artifacts/verification/`에 있고, Gradle XML/HTML 보고서는 `app/build/test-results`와 `app/build/reports`에 있다. CI도 전체 Android 테스트를 실행하고 보고서/에뮬 캡처/서명 APK를 `android-results` artifact에 보관한다.

## 남아 있는 실제 기기 확인

v0.2.2와 v0.2.3의 서명 인증서 SHA-256은 모두 `e49cbd46150600ad86cbd611c249b50d7906f675a936630d97e065d8978baffc`다. 에뮬레이터에서 앱 삭제 없이 업데이트 설치했고 versionCode 21 / versionName 0.2.3, 디버깅 비활성, 기존 설정 유지를 확인했다. 실제 로그인 세션의 업데이트 보존까지 직접 확인한 것은 아니다.

이번 결과는 실제 제공자 계정의 새 로그인, Claude/공식 API 실계정 조회, 삼성 One UI 런처/제조사 절전 정책까지 확인한 결과가 아니다. 기존 Codex/Grok 사용자 성공 기록은 개발 이력에 별도로 있다. 구형 WebView에서 웹 저장소 삭제는 비동기이며 캐시/디렉터리의 물리 삭제는 다음 프로세스 시작 때 완료된다.
