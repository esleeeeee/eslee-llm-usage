# v0.1.5 자동 수집 복구

작업일: 2026-09-11. v0.1.4 실기기 피드백에 따른 수정.

## 원인과 변경

기존 코드는 소비자 계정의 supportsBackgroundSync가 false여서 refreshAll에서 제외했고, refresh도 FOREGROUND_REQUIRED를 반환했다. 앱/위젯 새로고침은 로그인 Activity를 여는 동작이었다. v0.1.4의 수동 텍스트 붙여넣기는 요구한 자동 사용량 위젯을 충족하지 못해 제거했다.

- WebUsageReader는 기존 계정 profile로 공식 Usage 페이지를 로드하고 표시 텍스트를 읽는다. 첫 로드 완료에만 의존하지 않고 최대 40초 동안 비동기 콘텐츠를 기다린다. 계정별 세션을 그대로 사용하고 수집용 WebView는 완료/취소 시 파괴한다.
- 예약/앱/위젯 새로고침이 같은 Repository 수집 → Room 저장 → 위젯 갱신 경로를 사용한다.
- 웹 계정은 WorkManager로 15분 간격을 예약한다. 기존 API 갱신 주기와 분리하며 자동 갱신 끄기 및 Wi-Fi 전용 설정을 유지한다. Android 절전·작업 스케줄링에 의해 지연될 수 있다.
- 화면을 열어 둔 동안에는 5분 간격으로 갱신한다. Activity가 중지되면 DOM 감시를 중지한다.
- 사용량 읽기 버튼은 현재 공식 서비스 화면의 콘텐츠를 먼저 파싱해 저장한다. 예상 URL 경로와 다르다고 즉시 Usage URL을 다시 여는 동작을 제거했다. 잘못된 서비스/인증 화면은 저장하지 않는다.
- 저장 결과를 Repository에서 직접 반환하고 화면에 저장 완료 시각을 표시한다. 수집 실패 시 기존 스냅샷을 유지한다.
- 로그인 창을 닫는 것만으로 신규 계정과 세션을 자동 삭제하지 않는다. 계정 삭제는 별도 삭제 동작으로 수행한다.

## 검증

`WebUsageCollectionTest`는 실제 Android WebView 엔진을 사용하는 통합 테스트다. 로그인된 실제 Provider 계정 대신 테스트용 HTML과 테스트 쿠키를 사용한다.

1. 예상 URL과 다른 공식 호스트 경로에서 읽기 버튼을 눌러 새로운 DB 스냅샷이 생기고 페이지가 다시 이동하지 않는지 확인한다.
2. 세션 쿠키를 둔 프로필로 지연 표시되는 한국어 Usage를 수집한다.
3. 새 WebView를 만들어 같은 프로필 쿠키를 재사용하며 45%에서 40%로 변경된 사용량을 다시 저장한다.
4. Room의 결과를 위젯 mapper와 실제 Glance RemoteViews 렌더링에 전달해 40% 표시를 확인한다.
5. 파싱 실패 후 마지막 성공 스냅샷과 위젯 값을 유지하는지 확인한다.

GitHub Actions에 API 35 에뮬레이터 실행을 추가했다. 이 테스트가 실패하면 릴리즈 게시 단계는 실행하지 않는다. 실제 Google 2차 인증, Grok device verification, 사용자의 휴대폰 절전/런처 동작은 이 테스트의 검증 범위가 아니다.

## 에이전트별 업무

- 주 에이전트: 원인 진단, 자동 수집기·Repository·주기 작업·UI/위젯 연결 구현, 붙여넣기 제거, 통합 테스트 및 빌드/배포/문서 담당.
- collection_review (Astra Worker): 읽기 전용 검토. 인증보다 파싱을 먼저 하는 문제, 여러 계정에서 재시도 누락, 중지된 Activity DOM 감시를 지적했다. 세 문제를 주 에이전트가 수정했다. 검토 에이전트는 코드 수정/빌드를 하지 않았다.
- 이전 parser_fix의 한국어 파서 결과는 그대로 재사용했다. 이번에는 추가 파서 위임을 하지 않았다.
