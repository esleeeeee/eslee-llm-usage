# v0.2.4 검증 기록 — 2026-09-22

## 보고된 문제와 수정

- 로그인 실패 후 재시작: 기존 WebView에 로그인 URL만 다시 로드하던 동작을 제거했다. 해당 계정의 진행 중 수집을 취소하고 쿠키·웹 저장소를 폐기한 뒤 새 프로필과 WebView를 만든다. 계정 별칭과 다른 계정의 로그인은 유지한다. 전체 갱신 중 한 계정을 재시작해도 다른 계정의 수집은 계속된다.
- Grok 사용량: 서로 다른 DOM 노드에 있는 숫자와 `%`를 연결해 파싱한다. 영문 월 이름이 들어간 초기화 시각은 기기의 로컬 시간대로 해석한다. 수치의 used/remaining 의미는 여전히 명시적으로 확인해야 한다. 로그인 중 실제로 차단되던 `auth.grokusercontent.com` 호스트도 정확히 일치하는 경우에만 허용한다.
- 위젯 새로고침: 기존 18dp 아이콘 주변이 앱 열기 영역에 속해 있었다. 새로고침 터치 영역을 48dp로 확보하고 위젯 전체의 앱 열기 동작을 제거했다. 계정 링은 여전히 해당 계정 상세를 연다.
- 긴 오류 메시지가 계정 이름을 밀어내던 홈 카드와 상세 화면의 상태 표시를 아래 행으로 옮겼다.

## 실제 계정과 홈 화면 검증

`emulator-5554`, Android 15/API 35, Pixel Launcher, WebView 124, 720×1600/280dpi. 사용자 로그인 세션이 있는 기존 서명 APK에 업데이트 설치했다. 테스트 전용 APK로 덮어쓰거나 계정을 삭제하지 않았다.

1. 기존 v0.2.3 위젯을 홈 화면에 배치하고 새로고침 아이콘 주변을 누르면 MainActivity가 열리는 것을 재현했다.
2. 서명된 v0.2.4 후보에서 Grok 공식 페이지에 표시된 사용량과 초기화 시각이 앱에 저장되는 것을 확인했다. 앱 새로고침의 백그라운드 WebView 수집과 열린 웹 화면의 자동 수집을 각각 확인했다.
3. 실제 Pixel Launcher 위젯의 새로고침 터치 영역 가장자리를 ADB 터치로 눌렀다. 런처가 계속 foreground였고 버튼의 접근성 상태가 `Refreshing…`으로 바뀌었다가 완료 후 복원됐다.
4. 앱을 열기 전에 위젯 값 변경을 확인하고, 그 후 계정 링을 눌러 Codex와 Grok의 새 수집 시각 및 기록 추가를 확인했다. 일시적인 네트워크 실패 뒤 WorkManager 재시도도 발생했다.

실제 계정의 숫자·캡처·진단은 공개 저장소에 넣지 않는다. 로컬의 Git-ignored `artifacts/live-v024/`에만 보관한다. 공개 캡처는 synthetic 데이터만 사용한다.

## 자동 회귀 검증

별도 `eslee_qa_api35` / `emulator-5556`에 debug 및 instrumentation APK를 설치한다. 실제 로그인 세션이 있는 5554에서는 데이터 생성·삭제 테스트를 실행하지 않는다.

- 로그인 버튼을 직접 눌러 새 WebView와 프로필 생성, 이전 쿠키 제거, 다른 계정 쿠키 보존을 검증한다.
- 종료되지 않는 계정 수집 중 로그아웃이 5초 안에 완료되고 전체 갱신의 다른 계정이 계속 처리되는지 검증한다.
- SVG의 숫자와 `%`가 분리된 Grok 문서를 실제 WebView에서 캡처한다. 반복 백그라운드 수집, 영문 reset 파싱, Room 저장 및 값 변경을 검증한다.
- 실제 창에 붙은 AppWidgetHostView의 새로고침 터치를 통해 PendingIntent와 WorkManager를 실행한다. 콜백 함수를 직접 호출하는 방식은 사용하지 않는다.

최종 로컬 실행: JVM **75개**, Android **23개** 전부 통과(52.227초). Lint 오류 **0**, 경고 51. Debug 및 instrumentation APK 빌드 통과. 로그는 Git-ignored `artifacts/verification-v024/release-full-instrumentation.txt`와 `final-build.txt`에 있다.

배포 APK는 기존 GitHub Actions의 키로 서명한다. CI는 동일한 전체 Android 테스트를 다시 실행하며, `signed-release-apk` 산출물과 전체 보고서를 분리해 저장한다. 정식 릴리즈 경로는 [v0.2.4](https://github.com/esleeeeee/eslee-llm-usage/releases/tag/v0.2.4)다.

## 검증 범위

실제 서비스에 대한 검증은 에뮬레이터에 로그인된 Codex와 Grok 계정이다. Claude/API 실계정, 삼성 One UI의 절전과 런처별 배치는 이 결과에 포함하지 않는다. 비밀번호·인증 토큰·쿠키를 추출하거나 공개하지 않았다.
