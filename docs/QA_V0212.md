# v0.2.12 — 초기화 정보와 갱신 지연 수정 (2026-10-06)

기준: GitHub main `f3ba77e`, 배포 v0.2.11 (29). 기존 로컬 감사 변경은 원격과 동일함을 확인하고 보존했다.

## 사용자 진단에서 확인한 증상

- Android 16 / WebView 153의 Codex 수집은 수치가 있어도 초기화 시각과 리셋권이 누락됐다. Grok은 초기화 시각을 읽었다.
- 공식 Codex 페이지의 `사용량 설정을 불러올 수 없습니다.` 화면을 45초까지 기다렸다.
- 자동·수동 갱신이 겹쳐 실패 후 추가 수집이 발생했다. 일부 실행은 기기의 중단·네트워크 지연으로 더 오래 걸렸다.
- 실계정 API 응답·쿠키·토큰을 추출하지 않았다. 사용자 진단 원문을 공개 저장소에 복사하지 않는다.

같은 실계정 에뮬레이터에서 v0.2.11은 영어일 때 정보를 수집했고, 앱 언어를 한국어로 바꾸자 수치는 있지만 reset 시각과 리셋권은 없는 상태를 재현했다. 공식 페이지를 직접 열어 `사용 한도 초기화`, `사용 한도 재설정`, `초기화 사용`, `크레딧 사용 내역`과 접근성 날짜의 `2026년 … 화요일 오전 …시 …분 …초 GMT`, 만료 날짜의 `10. … 오후 … GMT 만료` 형식을 확인했다. 개인별 캡처는 ignored `artifacts/live-v0212`에만 보관한다.

## 수정

- 퍼센트를 읽었어도 초기화 정보가 빠지면 구조 캡처를 수행한다. 한 페이지의 두 캡처에서 동일 한도의 누락 시각과 리셋권 정보를 보완한다. 숫자의 기존 우선순위는 유지하며 이전 수집의 만료 시각을 임의로 재사용하지 않는다.
- 문서뿐 아니라 내부 스크롤 패널도 스크롤해 지연 표시되는 목록을 읽는다. 접근성에만 있는 사용량 라벨도 캡처한다.
- 리셋권 헤더만 뜬 로딩 상태는 unknown, 명시적인 0개는 확인 완료로 구분한다. 확인된 0개를 7초 더 기다리지 않는다.
- 한국어 연도 없는 월·일과 시각이 분리됐을 때 당일 시각으로 오인하는 문제를 수정했다. 리셋권 만료를 한도 초기화 시각으로 오인하지 않는다.
- 실제 확인한 새 한국어 제목·설명·버튼과 시·분·초 접근성 날짜, 점으로 구분된 만료 날짜를 지원한다. 명시된 GMT는 UTC로 해석하며 기기 시간대로 표시한다. 초기화 키워드 없이 날짜를 읽는 경우는 해당 한도 바로 아래의 명시적인 전체 날짜로 제한한다.
- 공식 화면의 명시적인 사용량 오류가 지속되면 즉시 실패를 반환하고 마지막 정상값을 유지한다.
- 겹친 갱신은 성공과 실패 모두 하나의 완료 결과를 공유한다. 이후 별도로 누른 새로고침은 다시 시도할 수 있다.
- 정보가 빠진 성공에도 제한된 사용량 주변 구조 진단을 남긴다.

## 검증

회귀에는 실제 WebView → 파서 → Room 저장, shadow root의 날짜·리셋권, 내부 패널 지연 목록, 명시적 0개 완료 시간, 공식 오류 화면의 신속한 종료, 동시 실패 요청과 이후 재시도를 포함한다. 로컬 전체 Android **37개** 통과(114.551초). 마지막 GMT 오프셋 보완 후 JVM **119개**, lint 오류 **0**/경고 60, Debug·Release·androidTest 빌드 통과. 최종 소스의 WebView 수집 **9개**를 다시 실행해 전부 통과했다(30.696초). 최종 CI 결과와 실계정 서명 APK 검증은 완료 후 기록한다.

실기기의 WebView 153과 네트워크 지연을 이 PC의 WebView 124로 동일하게 보장할 수는 없다. 앱의 불필요한 대기·중복 수집을 제거하되 제공자 페이지 로딩 시간과 Android 절전 시간은 별개다.
